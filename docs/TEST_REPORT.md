## 已知异常比对

- 产测：15 个全零返回被识别为无效 ACK；3 个源数据已重建 MOSI 但未重建 MISO 的事务存在长度差异，其后 3 个关联返回也被标记，因此共有 21 个 ERROR。
- PROG 按钮：9 个无效 TCS 返回被报告为 CRC 和命令回显异常，Boot 状态变化可正确识别。
- 多频点：复现 1 个 PROG 数据 CRC 错误、1 个同 CS TCS 返回 CRC 错误，以及 15 个全零应答；另有 4 个仅尾部 ACK 未识别的 WARNING。
- 三种原始特殊序列在产测数据中各出现 2 次，全部识别；扩展 `0x83` 使用合成输入验证，参考真实数据没有该序列。

## 覆盖范围

TCS/PROG 读写、CRC 独立向量、请求关联、同 CS 轮询、ErrCode、全零 ACK、特殊序列精确匹配、模式状态、长度异常、缺少 MISO、错误 SPI 设置、CS 边界、字段时间、反接方向、十进制编号，以及 1,500 组确定性随机输入和逐长度截断。

两份 Saleae CSV 共 1,297 笔事务分别按 Transactions 和 Fields 回放，检查输出时间不重叠、CS 关闭、方向识别和界面可见字段与核心结果一致。

额外损坏波形共提取 561 笔事务，其中 560 笔存在不满整字节的采样位；全部未被误标为有效。该文件仅用于损坏输入检查，不作为正确解析验收数据。参考边沿提取沿用已有脚本的去毛刺规则，插件不推断或修补缺位。

## 复现

单元测试无需外部资料：

```sh
python -m unittest discover -v
```

持有参考目录时运行：

```sh
python -m tests.validate_reference --reference /path/to/reference
```

详细结果生成于本地 `validation/report.json`，其中包含原始字节和本机路径，因此已被 Git 忽略，不进入仓库或发布包。参考目录需保留回归脚本使用的数据文件、已有分析摘要和边沿读取脚本。
